# Threat model

## Protected assets

上游地址、管理员凭据、TOTP 秘钥、恢复码、路由访问能力、审计记录，以及 Emby 请求中的认证头和 Cookie。

## Trust boundaries

客户端到公网代理、管理员到本机管理监听器、AegisRelay 到上游、进程到加密数据文件是四个独立边界。TLS 由前置代理终止时，前置代理属于受信任计算基。

容器到宿主机是第五个边界。容器以非特权用户运行，碰不到宿主机的 Nginx 和证书；需要切换域名时，它在自己的数据目录里放一个请求文件，由 systemd 的 path 单元启动宿主机脚本（root）来处理。数据目录属于容器用户，所以宿主机脚本把那里的一切都当作不可信输入。

## Main threats and controls

| Threat | Primary controls | Residual risk |
|---|---|---|
| 管理员撞库 | scrypt、TOTP、登录限速、短会话 | 主机被控后无法保护 |
| CSRF/XSS | CSRF token、Strict cookie、CSP、DOM textContent | 浏览器扩展仍可能读取页面 |
| 客户端 URL 泄露 | 单路由随机密码、加密存储、HMAC 校验、no-referrer、无 URI 日志、快速轮换 | 已登录管理员、外层代理和客户端可能读取完整地址 |
| SSRF/云元数据访问 | URL 解析、默认拒绝私网/环回/链路本地、禁止 URL 凭据 | 显式允许私网后风险上升 |
| 数据文件被读取 | AES-256-GCM、0600、Docker 只读根文件系统 | 主密钥同时泄露时失效 |
| 上游身份泄露 | 不转发 Forwarded/XFF、覆盖 Host、清理 hop-by-hop 头 | Emby 自身可识别代理出口 IP |
| 开放代理 | 只有已配置别名 + 正确独立密钥可路由 | 密钥泄露前仍可被使用 |
| 容器被攻陷后借请求文件影响宿主机 | 请求只在是不超过 64 KiB、内容为 UTF-8 JSON 对象的普通文件时才读取，打开时不跟随链接、不等待；每个字段整体重新校验（含换行的值一律拒绝，不能靠其中一行合法混过去；证书邮箱里对 Compose 和 certbot 是语法的字符——`$`、反引号、双引号、反斜杠、开头的 `#`、`'`、`-`——以及非 ASCII 和控制字符一律拒绝，进不了 `.env`）后才交给 Nginx 和 certbot；脚本结束时一定移走请求，不会被同一个请求反复触发，没有执行的请求会得到「失败」的答复而不是让容器一直等；脚本先切到 `/` 再运行，不会加载容器数据目录里的文件；状态文件不按容器能改动的文件名写入或改权限 | 容器仍能让宿主机为格式合法的域名申请证书、切换本机的直连地址 |

## Non-goals

本项目不隐藏代理服务器 IP，不绕过上游授权，不提供匿名网络，也不能保护已被完全攻陷的宿主机或管理员设备。
